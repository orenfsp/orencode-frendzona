# Сценарий демонстрации прототипа

Ожидаемая продолжительность: 5–7 минут. Все демо-данные вымышлены.

## 1. Вход и роли

1. Открыть `http://localhost:8080`.
2. Войти под `federation@fsp56.ru`, пароль `demo`.
3. Показать, что роль Федерации видит создание и публикацию соревнований, реестр и модерацию заявок.
4. Выйти и войти как `morozov@fsp56.ru`, пароль `demo`. У этой учётной записи назначены роли спортсмена и тренера; активную роль можно менять только между назначенными ролями.
5. Показать форму публичной регистрации. В качестве роли можно выбрать спортсмена, тренера или судью; самостоятельно зарегистрировать Федерацию нельзя.

## 2. Создать и опубликовать соревнование

1. Под ролью Федерации открыть «Соревнования» и нажать «Создать соревнование».
2. Указать название, дисциплину и тип из серверного справочника, уровень, формат, возрастную группу, дату, место, срок заявок, календарный план и положение соревнования.
3. Сохранить черновик, затем нажать «Опубликовать».
4. Проверить, что статус изменился на «Регистрация».

## 3. Регистрация спортсмена и подтверждение профиля

1. Выйти и создать новый аккаунт спортсмена. Для теста указать дату рождения, возрастную группу и дисциплину, совпадающие с соревнованием.
2. Подтвердить согласие на обработку персональных данных. Для несовершеннолетнего спортсмена также заполнить ФИО законного представителя и его согласие.
3. Войти под Федерацией и открыть «Реестр участников».
4. Нажать «Подтвердить» рядом с профилем со статусом «На проверке».

## 4. Заявка и модерация

1. Войти под подтверждённым спортсменом.
2. Открыть «Соревнования» и подать заявку на соревнование со статусом «Регистрация», у которого совпадают дисциплина и возрастные условия.
3. Вернуться под Федерацией, открыть «Соревнования» и обработать заявку в блоке «Заявки на рассмотрении».
4. Одобрить заявку. Счётчик участников соревнования обновляется на основе одобренных заявок.

## 5. Результаты и роли

- Федерация может назначить судью через API и сохранять результаты.
- Судья может сохранять результаты только соревнования, на которое он назначен Федерацией.
- Результаты и протоколы доступны через API; полноценный экран ввода результатов и отдельные рабочие экраны тренера/судьи ещё требуют доработки.
- В разделе «Документы» проверить выгрузку протокола DOCX/XLSX, отчёта спортсмена DOCX, реестра XLSX, отчёта о численности XLSX и проекта приказа DOCX.
- В разделе «Рейтинг» проверить фильтр по возрастной группе и дисциплине; в «Сборной области» проверить фильтры кандидатов, ручной выбор и сохранение состава.
- Новые профили спортсменов ожидают подтверждения; пока профиль не подтверждён, заявка на соревнование отклоняется сервером.

## Запуск и проверка

```bash
docker compose up --build
```

- Веб-интерфейс: `http://localhost:8080`
- API health: `http://localhost:8081/api/health`

Для локальной проверки API сначала выполните вход и используйте полученный токен в заголовке `Authorization: Bearer <token>`. Например:

```bash
curl -X POST http://localhost:8081/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"federation@fsp56.ru","password":"demo"}'
```

## Ограничения прототипа

Перед реальной эксплуатацией нужно прогнать интеграционные тесты регистрации и ролевого доступа, проверить все бизнес-сценарии на развёрнутом стенде, завершить UI ввода результатов и рабочие формы привязки/назначений/разрядов/категорий, сверить шаблоны документов и официальный регламент рейтинга, добавить rate limiting и проверить конфигурацию секретов. Не использовать демонстрационные пароли в публичном развёртывании.

## 6. Проверка оформления

1. На экране входа нажать переключатель темы: режимы циклически меняются между «Авто», «Светлая» и «Тёмная».
2. В режиме «Авто» оформление следует настройке светлой/тёмной темы операционной системы и обновляется при её изменении.
3. Выбранная вручную тема сохраняется после перезагрузки страницы; выбор «Авто» возвращает системное управление.
4. Проверить логотип ФСП на экране входа и в боковой панели, а также светлую/тёмную темы на мобильной ширине.
5. Надпись рядом с индикатором обновления должна различать данные, загруженные из API, и демонстрационные данные при недоступности API.

# Полный набор тестовых сценариев

Пароль всех демо-аккаунтов — `demo`. Адрес: `http://localhost:8080`. Все данные вымышлены.

## Аккаунты и роли

| Аккаунт | Роли | Для чего |
|---|---|---|
| `federation@fsp56.ru` | Федерация | создание соревнований, модерация, реестр, документы, приказ |
| `morozov@fsp56.ru` | Спортсмен + Тренер | переключение ролей (С1), заявки, подопечные |
| `krylova@fsp56.ru` | Тренер | заявки за спортсменов, нормативы, группы |
| `sokolova@fsp56.ru` | Спортсмен | заявки, результаты, апелляции, справка |
| `judge@fsp56.ru` | **Судья** | кабинет судьи (см. ниже) |
| `volkov@fsp56.ru` | Тренер + Судья | переключение ролей тренер ↔ судья |
| `ministry@fsp56.ru` | Министерство | только просмотр (любая запись → 403) |

## Как зайти судьёй и что он может

1. На экране входа ввести `judge@fsp56.ru` / `demo`. Роль «Судья» назначается автоматически, переключателя нет, потому что у аккаунта одна роль.
2. Чтобы увидеть переключение ролей, войти как `volkov@fsp56.ru`: в шапке справа выпадающий список роли (Тренер / Судья). Права на сервере проверяются по активной роли.
3. Меню судьи: Главная, Соревнования, Документы, Апелляции, Организации, Путь и справочник, Уведомления.
4. Что судья делает в интерфейсе:
   - **Документы → блок судейства (Д12):** справка о составе судейской коллегии соревнования и отчёт по себе (DOCX/XLSX). Чужие данные сервер не отдаёт.
   - **Апелляции:** фиксация рапорта о нарушении и санкции (предупреждение, техническое поражение, дисквалификация).
   - **Соревнования, Организации:** просмотр.
5. Рабочие экраны судьи (меню «Судейство» и «Результаты»):
   - **Судейство:** своя категория со сроком действия (предупреждение за 90 дней), назначения на соревнования с должностью, подача заявки на присвоение или подтверждение категории и статус заявки.
   - **Результаты:** ввод места и баллов участников соревнования, на которое судья назначен (для остальных сервер возвращает 403), выгрузка протокола XLSX/DOCX.
6. Те же действия доступны через API (примеры ниже). Токен: `POST /api/auth/login`, дальше заголовок `Authorization: Bearer <token>`.

```bash
TOKEN=...  # из ответа /api/auth/login
curl -s localhost:8081/api/assignments -H "Authorization: Bearer $TOKEN"
curl -s localhost:8081/api/competitions/1/participants -H "Authorization: Bearer $TOKEN"
curl -s -X POST localhost:8081/api/categories -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"requested_category":"Судья первой категории","kind":"присвоение"}'
curl -s -X POST localhost:8081/api/competitions/1/results -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"items":[{"athlete_id":1,"place":1,"score":300}]}'
```

Федерация принимает решение: `POST /api/categories/{id}/decide` (`{"status":"approved","note":"..."}`), назначает судью: `POST /api/competitions/{id}/judges` (`{"judge_id":1,"position":"Главный судья"}`).

## Сценарии по критериям (С1–С10)

| № | Сценарий | Шаги проверки | Где |
|---|---|---|---|
| С1 | Мультироль | Войти `morozov@` → переключить Спортсмен ↔ Тренер в шапке. Меню меняется. Под ролью спортсмена вызвать тренерский API → 403 | UI + API |
| С2 | Создать и опубликовать соревнование | Федерация → Соревнования → «Создать»: дисциплина, тип из справочника, возрастная группа, календарный план (ЕКП/областной), положение → «Опубликовать» → статус «Регистрация» | UI |
| С3 | Заявка и модерация | `sokolova@` → подать заявку на соревнование; заявка с неподходящим возрастом или дисциплиной отклоняется сервером. Федерация → «Заявки на рассмотрении» → одобрить | UI |
| С4 | Привязка тренер ↔ спортсмен | Тренер (`krylova@`) → «Подопечные» → найти спортсмена, выбрать дисциплину → «Отправить запрос». Выйти, войти спортсменом → «Подопечные» → «Подтвердить» (можно приостановить, завершить, возобновить). У одного спортсмена может быть несколько тренеров по разным дисциплинам | UI |
| С5 | Результаты → протокол → история | Федерация или назначенный судья → «Результаты» → выбрать соревнование → указать место и баллы участникам с одобренными заявками → «Сохранить». Появляются кнопки протокола XLSX/DOCX. Спортсмен → «Результаты»: запись в истории выступлений. Участник без одобренной заявки в протокол не попадёт (422) | UI |
| С6 | Судейская коллегия и категория | Федерация → «Судейство» → выбрать соревнование, судью и должность → «Назначить». Судья (`judge@`) → «Судейство»: видит назначение и срок категории, подаёт заявку на категорию. Федерация → «Заявки судей» → «Присвоить» (срок 4 года) или «Отклонить» | UI |
| С7 | Разряд | Тренер или спортсмен без тренера → «Разряды» → выбрать соревнование и результат, запрашиваемый разряд → «Подать заявку» (спортсмен с активным тренером получает отказ: заявку подаёт тренер). Федерация → «Разряды» → номер приказа → «Присвоить» (срок 2 года). Блок «Истекающие разряды» показывает сроки менее 90 дней | UI |
| С8 | Реестр и численность | Документы → «Отчёт о численности» и «Реестр» → XLSX: годы, организации, дисциплины, возраст, муниципалитеты | UI |
| С9 | Рейтинг и сборная | Рейтинг: фильтры дисциплина/возраст, прозрачный расчёт (баллы, ×1,2 при двух призовых, дисквалифицированные исключены). Сборная: отбор из рейтинга, ручной состав, список и проект приказа DOCX | UI |
| С10 | Документы | Документы → протокол, отчёт по спортсмену, реестр, приказ. Открыть файлы и проверить содержимое | UI |

## Регистрация с подтверждением почты

1. Экран входа → «Регистрация» → заполнить форму → отправить код на почту → ввести код.
2. Если `SMTP_HOST` не задан, код печатается в логах: `docker compose logs api`.

## Проверка оформления шапки

На ширине 1240–1700 px вкладки меню (у Министерства и Федерации их 9–11) прокручиваются по горизонтали и не заезжают на иконки справа; на меньшей ширине включается бургер-меню.
