# Telegram-бот ФСП 56: подключение и проверка

Этот проект использует официальный Telegram Bot API через **long polling**. Приложение само опрашивает Telegram на наличие новых сообщений. Для локальной разработки на `localhost` не требуются домен, публичный HTTPS-сервер, туннель или webhook.

## 1. Создать бота

1. Открой Telegram и найди официальный аккаунт [@BotFather](https://t.me/BotFather).
2. Отправь `/newbot`.
3. Задай отображаемое имя, например `ФСП 56 — Оренбургская область`.
4. Задай username. Он должен быть уникальным и заканчиваться на `bot`, например `FSP56OrenburgBot`.
5. BotFather вернёт токен. Считай его паролем: не публикуй его в чате, скриншотах, исходниках или Git. Если токен случайно раскрылся, отзови его через BotFather и используй новый.

Официальная инструкция Telegram: https://core.telegram.org/bots/features#botfather

## 2. Добавить токен в проект

Открой терминал в папке `Test1` — там, где лежит `docker-compose.yml`.

```bash
# Создай .env только если его ещё нет, чтобы не затереть текущие настройки.
[ -f .env ] || cp .env.example .env
nano .env
```

Заполни только токен:

```dotenv
TELEGRAM_BOT_TOKEN=ВСТАВЬ_ТОКЕН_ОТ_BOTFATHER
TELEGRAM_DEFAULT_CHAT_ID=
```

`TELEGRAM_DEFAULT_CHAT_ID` можно оставить пустым на первом этапе. Он нужен только для общего чата/канала с системными сообщениями.

Файл `.env` исключён из Git. Не отправляй никому токен и не вставляй его в сообщения об ошибках.

## 3. Запустить проект

В той же папке выполни:

```bash
sudo docker compose up --build -d
```

Посмотри, стартовал ли бот:

```bash
sudo docker compose logs --tail=100 api
```

В логах ожидается сообщение `Telegram bot long polling started`. Если увидишь `Unauthorized`, проверь токен: вероятно, он скопирован не полностью или уже отозван. Если появится сообщение о другом активном способе получения updates, код сам пытается удалить webhook; перезапусти API после проверки токена.

Проверь API и конфигурацию бота:

```bash
curl -sS http://localhost:8081/api/health
curl -sS http://localhost:8081/api/integrations/telegram/status
```

При заданном токене статус должен содержать `"configured":true`, `"polling_enabled":true` и `"mode":"long_polling"`. Этот статус подтверждает наличие конфигурации, но окончательная проверка — получить реальный ответ от бота в Telegram.

## 4. Проверить команды

1. Открой ссылку на своего бота из сообщения BotFather или найди его username.
2. Нажми **Запустить** или отправь `/start`.
3. Последовательно отправь команды:

```text
/help
/events
/rating
```

Ожидаемое поведение:
- `/start` и `/help` показывают список команд;
- `/events` запрашивает ближайшие соревнования у API платформы;
- `/rating` запрашивает топ рейтинга из API платформы.

Если список соревнований/рейтинг пустой, это не обязательно ошибка Telegram. Сначала проверь, что соответствующий API возвращает данные.

Если бот молчит, проверь логи:

```bash
sudo docker compose logs -f api
```

Убедись, что сервис API не перезапускается, в `.env` нет пробелов или кавычек вокруг токена, и статус интеграции показывает `configured: true`. Telegram Bot API поддерживает long polling через `getUpdates`; polling и webhook одновременно использовать нельзя. Официальная документация: https://core.telegram.org/bots/api#getupdates

## 5. Связать Telegram с аккаунтом ФСП 56

Это включает персональные уведомления для конкретного аккаунта.

1. В веб-платформе `http://localhost:8080` войди тестовым пользователем.
2. Перейди в раздел **Уведомления** и нажми **Получить код подключения**.
3. В личном чате бота отправь команду с отображённым кодом, например `/link 12345678` — используй реальный код из платформы.
4. Код состоит из восьми цифр, действует десять минут и используется один раз.
5. Бот должен подтвердить привязку, а интерфейс через несколько секунд отобразит подключённое состояние.

Привязку нужно делать в личном чате, а не в группе. Telegram не разрешает боту первым начать диалог с пользователем, поэтому пользователь должен нажать «Запустить» до получения персональных сообщений.

## 6. Проверить персональные уведомления

После успешной привязки выполни в платформе действие, которое отправляет уведомление связанному пользователю, например обработай тестовую заявку спортсмена. Сообщение должно прийти в Telegram.

В текущей реализации уведомления предусмотрены для решения по заявке на соревнование, решения по разряду, решения по судейской категории и публикации результатов. Плановые напоминания за несколько дней до истечения срока пока не реализованы.

Чтобы отключить уведомления, используй кнопку **Отключить** в разделе «Уведомления». Старый код привязки использовать повторно нельзя.

## 7. Необязательный общий чат

Если хочешь получать системные сообщения в рабочий чат Федерации:

1. Создай группу или канал в Telegram и добавь туда бота. Для отправки в канал у бота должны быть соответствующие права администратора.
2. В нужном чате отправь `/chatid`. Бот ответит идентификатором чата.
3. Запиши этот ID в `TELEGRAM_DEFAULT_CHAT_ID` в `.env`, обычно у группы он выглядит как отрицательное число.
4. Пересоздай контейнер API, чтобы переменная окружения обновилась:

```bash
sudo docker compose up -d --build --force-recreate api
```

Проверь `/api/integrations/telegram/status`: поле `default_chat_configured` должно быть `true`. Проверь в самом чате, что бот действительно добавлен и может отправлять сообщения. Для канала с публикациями потребуется отдельно узнать его chat ID и дать боту права администратора.

## 8. Диагностика и безопасность

- `TELEGRAM_BOT_TOKEN` хранится только в локальном `.env`; не коммить его.
- Не используй реальный аккаунт или личные данные для публичной демонстрации; создай тестового пользователя.
- Если токен не работает, проверь его через команду Bot API `getMe` или отзови/создай новый у @BotFather.
- Long polling держит запрос к Telegram открытым до появления сообщений. Это нормально; он не блокирует HTTP API-потоки.
- Telegram polling и webhook взаимоисключающие режимы. Данный проект использует polling и при запуске удаляет ранее заданный webhook, сохраняя очередь ожидающих событий.
- Полная сборка/реальная доставка должны подтверждаться на твоём Docker-стенде. Наличие файла токена или статуса `configured` само по себе не доказывает, что бот отвечает.
