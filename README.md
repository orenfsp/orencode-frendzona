# ОренКод — стартовый прототип цифровой платформы ФСП

Первый технический срез для хакатона: интерфейс региональной платформы, API на Go, PostgreSQL, Docker Compose и интеграция с Telegram-ботом для справки о соревнованиях/рейтинге и персональных уведомлений.

В текущей версии реализованы регистрация, вход, сессии и серверная проверка активной роли для защищённых API-маршрутов.

## Что сделано (Текущий функционал)

### Платформа и интерфейс
- **Панель управления:** главная страница со сводными показателями, ближайшими соревнованиями, рейтингом и уведомлениями.
- **Основные разделы:** «Соревнования», «Участники», «Рейтинг», «Сборная», «Документы» и «Уведомления».
- **Авторизация и сессии:** регистрация и вход по email/паролю, bcrypt-хеширование, 12-часовая серверная сессия.
- **Ролевая модель:** разделение прав (Федерация, Тренер, Спортсмен, Судья) с возможностью переключения ролей внутри аккаунта.
- **Профили:** проверка спортивных дисциплин, возраста, возрастных групп и согласия законного представителя для несовершеннолетних.
- **Управление соревнованиями:** создание соревнований через интерфейс и сохранение в PostgreSQL. Спортсмены могут подавать заявки, а Федерация или назначенный судья — сохранять результаты.

### Backend и Инфраструктура
- **REST API:** эндпоинты для соревнований, реестра спортсменов, рейтинга, сборной и уведомлений.
- **База данных:** автоматическое создание таблиц и заполнение базы демонстрационными данными при первом запуске.
- **Архитектура:** контейнеризация через Docker Compose, Nginx в качестве reverse proxy, наличие health endpoint и базовая проверка входных данных.

### Интеграция с Telegram
- **Telegram-бот (@FSP56OrenburgBot):** работает в режиме long polling (не требует публичного HTTPS-вебхука для локальной проверки).
- **Команды бота:** `/start`, `/events` (список соревнований), `/rating` (просмотр рейтинга), `/help`.
- **Связывание аккаунтов:** команда `/link КОД` для одноразовой привязки Telegram к профилю на платформе для получения персональных уведомлений (статусы заявок, разряды, результаты).

## Запуск проекта

### Среда развертывания (Docker Compose)
Для запуска необходим Docker с поддержкой Compose v2. Из корневой директории проекта выполните:

```bash
docker compose up --build
```

**Доступные сервисы после запуска:**
- Веб-интерфейс: <http://localhost:8080>
- API Health Check: <http://localhost:8081/api/health>
- PostgreSQL: доступен внутри compose-сети на сервисе `db`. Состояние хранится в volume `postgres_data`.

Для полного сброса демонстрационной базы данных выполните:
```bash
docker compose down -v
docker compose up --build
```

### Локальная разработка API (без Docker)
Требуются установленные Go 1.23+ и PostgreSQL. Из каталога `backend`:

```bash
cd backend

# Для bash:
export DATABASE_URL=postgres://orenkod:orenkod_local@localhost:5432/orenkod?sslmode=disable
# Для PowerShell:
# $env:DATABASE_URL="postgres://orenkod:orenkod_local@localhost:5432/orenkod?sslmode=disable"

go run ./cmd/api
```

Запуск тестов и проверок кода:
```bash
go test ./...
go vet ./...
go build ./...
```


## Спецификация API

| Метод | Путь | Назначение | Доступ |
|---|---|---|---|
| `GET` | `/api/health` | Проверка работоспособности сервиса | Публичный |
| `POST` | `/api/auth/register` | Регистрация нового пользователя | Публичный |
| `POST` | `/api/auth/login` | Аутентификация и выдача токена сессии | Публичный |
| `POST` | `/api/auth/logout` | Завершение текущей сессии | По сессии |
| `GET` | `/api/auth/me` | Получение профиля текущего пользователя | Bearer Token |
| `POST` | `/api/auth/switch-role` | Смена активной роли аккаунта | Bearer Token |
| `GET` | `/api/dashboard` | Сводные показатели главной страницы | Bearer Token |
| `GET` | `/api/competitions` | Просмотр списка соревнований | Публичный |
| `POST` | `/api/competitions` | Создание нового соревнования (черновик) | Только Федерация |
| `GET` | `/api/athletes` | Просмотр реестра спортсменов | Публичный |
| `GET` | `/api/rating` | Просмотр текущего рейтинга по очкам | Публичный |
| `GET` | `/api/team` | Просмотр демонстрационного состава сборной | Публичный |
| `GET` | `/api/notifications` | Список системных уведомлений | Bearer Token |
| `GET` | `/api/integrations/telegram/status` | Проверка статуса конфигурации бота | Публичный |
| `GET` | `/api/integrations/telegram/link-status` | Проверить привязку Telegram к профилю | Bearer Token |
| `POST` | `/api/integrations/telegram/link-code` | Сгенерировать код привязки (на 10 минут) | Bearer Token |
| `DELETE` | `/api/integrations/telegram/link` | Отвязать аккаунт Telegram от профиля | Bearer Token |

Для защищенных маршрутов необходимо передавать заголовок `Authorization: Bearer <token>`.

Пример тела запроса (`JSON`) для создания соревнования (`POST /api/competitions`):
```json
{
  "title": "Кубок Оренбургской области",
  "discipline": "Программирование",
  "competition_type": "Региональный",
  "age_group": "Юниоры",
  "starts_at": "2026-11-21T10:00:00+05:00",
  "location": "Оренбург"
}
```

## Настройка Telegram-бота

Для работы уведомлений и команд бота в локальном окружении или Docker:
1. Создайте бота через `@BotFather` и получите токен.
2. Задайте переменную окружения `TELEGRAM_BOT_TOKEN` в файле конфигурации или передайте её в Docker Compose.
3. Подробное описание процесса настройки находится в файле `docs/TELEGRAM_BOT_GUIDE.md`.
